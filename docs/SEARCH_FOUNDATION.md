# OMNIARK 검색 기반 원칙

## 목표

검색·AI 검색에 맞춘 별도 글쓰기 요령이 아니라, 사람이 읽는 글의 정체와 기술 정보가 정확히 일치하게 유지한다.

## 공개 글의 단일 원본

- `app/content/posts/*.json`만 공개 글의 원본이다.
- Studio의 초안 폴더와 작성 중인 Markdown은 사이트맵과 공개 경로에 포함되지 않는다.
- 글의 `title`, `description`, `date`, `updatedAt`, `tags`, `heroImage`, `socialImage`는 보이는 페이지와 메타데이터·구조화 데이터가 함께 사용한다.
- 초안의 원본 경로·근거 메모는 내부 검토 정보다. 공개 전환은 이 정보를 공개 JSON에서 제외한다.

## 게시 시 자동으로 갖춰지는 것

- 글별 정식 주소(canonical), 제목, 설명, Open Graph/Twitter 정보
- 개발 노트는 `BlogPosting`, 활용 가이드는 `Article`, 두 종류 모두 `BreadcrumbList`
- 공개 글만 담는 `sitemap.xml`과 이를 가리키는 `robots.txt`
- 첫 공개일은 공개 전환 시 기록하고, 이후 갱신은 첫 공개일을 보존한 채 별도 수정일로 기록

## 편집 원칙

- 설명은 글에 실제로 있는 결론·대상·사건만 쓴다.
- 사건일과 최초 공개일은 구분한다. 모르는 수정일을 만들지 않는다.
- 대표 이미지를 등록한 경우에만 이미지 메타데이터를 낸다.
- 소셜 미리보기 비율이 본문 표지와 다르면 `socialImage`를 별도로 등록한다. 없으면 본문 표지를 사용한다.
- 질문 하나에 실제 답변이 모인 페이지일 때만 `QAPage`를 검토한다. 일반 에세이에 FAQ/Q&A 마크업을 억지로 붙이지 않는다.
- 구조화 데이터는 풍부한 검색결과를 약속하지 않는다. 보이는 본문을 정확히 해석하게 하는 보조 정보다.

## 발행 뒤 확인

1. 배포된 글의 `<title>`, canonical, 설명, OG 이미지와 JSON-LD를 실제 HTML에서 확인한다.
2. Google Search Console과 네이버 서치어드바이저에 `https://omniark.co/sitemap.xml`을 제출한다.
3. 색인·검색어·클릭 데이터가 쌓인 뒤 제목과 내부 연결을 개선한다. 키워드를 덧붙여서 해결하지 않는다.
